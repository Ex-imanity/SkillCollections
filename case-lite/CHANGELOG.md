# Changelog — case-lite

本文件记录该 skill 的版本变更。版本号的唯一真相是 `SKILL.md` frontmatter 的 `version` 字段，
本文件顶部条目必须与之一致（由 `tests/test_repo_conventions.py` 校验）。

版本语义按**对使用者坏了什么**判定：

- **MAJOR** — 已有产物或用法失效，需要迁移
- **MINOR** — 新增能力，向后兼容
- **PATCH** — 修 bug、改文档、调措辞，行为不变

规则：不是每个 commit 都要升版本，但每次升版本必须在此留下条目。

## 1.2.0 - 2026-09-20

### 场景分层从「可选建议」变成流程里的必做检查

1.1.0 支持了多级场景，但拆分判据只写在 full.md 格式规范里，Step 3 仅有一句交叉引用，
且没有任何要求 agent 说明分层决策的产物。实际使用中 agent 稳定产出扁平结构，
用户无法从结果里区分「评估后认为不必拆」和「根本没评估」。

- Step 3c 改为**只按单层场景草拟**，草拟完不直接展示给用户
- 新增 **Step 3d 场景分层复核**：逐个顶层场景评估是否拆子场景。
  检查必做，拆分可选；结论以复核表（场景 / 测试点数 / 拆或不拆及理由）
  随 `structure.md` 一起展示，且必须覆盖全部顶层场景
- 「何时拆子场景」判据从 `## full.md 格式规范` 移入 Step 3d，并补了一张按测试点数分档的速查表
  （≤5 不拆 / 6–8 视维度 / >8 必须逐条对照）
- Step 4 新增合法回头路：展开时发现某场景该拆，须停下来提出 `structure.md`
  修订并经用户确认，不得在 `full.md` 里私自调整分层或重编号
- 复核表只出现在给用户的确认消息里，不写进 `structure.md`

`writeback.py` 与 `full.md` / `structure.md` 的格式均无改动。

## 1.1.0 - 2026-09-03

新增两项能力，均向后兼容：已有 `case-lite-output/` 产物无需迁移，
旧格式 `full.md` 解析结果逐字节不变（18 份历史语料验证）。

### 产物目录支持迭代分组

- Step 1 引导输入新增可选的「迭代名称」，不填则行为与旧版完全一致
- 提供迭代名称时产物路径变为 `case-lite-output/{迭代slug}/{需求slug}/`，
  并在迭代目录维护跨需求的 `iteration-index.md`（需求清单、搬山 caseId、进度）
- 指定迭代但同名需求的扁平目录已存在时，提示用户选择「迁移」或「新建」，不自动移动已有产物

### 场景支持多级嵌套

此前所有场景节点必须同层，场景的直接子节点只能是测试点。现在场景可任意层嵌套。

- **编号即路径**：层级由编号段数决定（`场景3.1` 的父节点是 `场景3`），
  不看 markdown 标题的 `#` 级别；`执行步骤` / `预期结果` 标记与深度解耦
- **不允许混搭**：任一场景的直接子节点不能同时包含子场景和测试点
- 建议嵌套深度 3 层（仅提示），硬上限 20 层（阻塞）
- `writeback.py` 校验分三档：阻塞错误 / 警告 / 建议。
  修正了旧版警告在非 dry-run 模式下不拦截的问题——结构性错误现在两种模式都阻塞
- dry-run 输出改为完整树形概览，编号取自原文而非按位置重排


## 1.0.0 - 2026-09-03

首个标注版本。此前变更见 git 历史，不追认为 release。

当前能力基线：

- 飞书 Docx / Wiki / 云空间原生 Markdown 选章 → 场景结构 → 完整用例 → 可选自检 → 写回搬山
- 支持递归发现并按需纳入 wiki 子文档
- 场景为单层结构，场景的直接子节点是测试点
- `writeback.py` 解析 `full.md` 并写回搬山，写回前必须 dry-run
