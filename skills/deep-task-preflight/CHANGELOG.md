# Changelog — deep-task-preflight

## 1.2.1 - 2026-10-28

- 合成评估迁到仓库级 evals/deep-task-preflight，维护者新增 adapter 模板迁到 docs/maintainers；保留实际 preflight 模板、检查表和各领域 adapter。

## 1.2.0 - 2026-10-06

- 重构核心流程为通用 preflight、gate、追踪和四级验证梯度，核心只保留跨领域规则。
- 收窄触发条件，新增 Medium 模式、阻塞退出条件和范围变化重新 gate 规则。
- 将代码、文档、UI、数据管道、调试及合同/运维规则移至 `references/adapters/`。
- 补充轻量、负向、`NEEDS INPUT`、`BLOCKED`、handoff 和 Medium 模式评估方向，降低场景补丁风险。

## 1.1.0 - 2026-10-06

- 新增 Reference-first：先对照已有客户端、服务端、解析器、渲染器或数据合同，再设计替代实现。
- 新增输入—转换—输出闭环，覆盖多卡、多轮、重试、重新生成、结构化数据和媒体证据的完整性。
- 新增 UI 实际渲染、写入后读回、状态/计数刷新和数据正确性专项验收。
- 新增 LLM Judge/报告类任务的证据合同检查，防止用 Prompt 修改掩盖上游数据丢失。

## 1.0.0 - 2026-10-06

- 新增实现前 Preflight Packet：目标、动机、受众、范围、验收、未知项、风险、改动面和验证矩阵。
- 新增轻量/完整模式，按任务复杂度选择流程，避免小改动被过度流程化。
- 新增陌生评审者、可追溯性、边界、证据、反向空间、失败路径和返工检查。
- 新增实现后的逐项验收回流，以及与 MRS、代码风格和跨 Agent 评审 Skill 的协作约定。
