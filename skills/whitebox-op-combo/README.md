# whitebox-op-combo

白盒操作组合分析：能看到代码时，把一个功能的用户操作拆成原子动作，排列组合正向与异常的操作顺序，
映射到代码执行路径，在测试执行前定位缺陷可能出现在哪里，并产出测试用例。

## 适合什么时候用

- 功能涉及多个会修改同一对象的操作（点赞、重新生成、编辑、撤销、加入收藏……），担心操作之间相互影响
- 有异步落库、多级缓存、多个存储层，担心"刚操作完读到旧值"
- 有退出重进、切后台、杀进程、流式输出中断等生命周期问题
- 多端（Android / iOS / Web）各自实现同一协议，担心行为不一致
- 需要判定一个问题到底是服务端还是客户端的

只有需求文档、没有代码时用 `case-lite`。

## 核心思路

两个操作只有读写了同一份状态才会相互影响。所以：

1. **静态**：列出功能的所有状态读写点（字段 × 存储层 × 同步/异步 × 代码位置）
2. **原子化**：按读写集把用户动作归成原子动作
3. **组合**：只对存在读写依赖的原子对推演代码路径（含"替换后读到没重写的旧字段"），其余剪枝
4. **收敛**：每个候选要么被代码证实、要么被排除、要么交给实测

## 原子动作谁来拆、怎么保证覆盖

这是方法能不能落地的关键。本 skill 的做法：

- **agent 从代码穷举，人只审一次**。原子的定义是"读写集等价类"——两个 UI 动作如果读写完全相同的状态，
  就是同一个原子（折叠为变体）；读写集不同，哪怕 UI 上看起来一样，也要拆开。这个定义让拆分可以从代码机械推出，
  不依赖个人经验。
- **四个来源三角互证**：代码（入口 → 读写点，主来源）、需求与设计稿（补代码里看不出的用户意图）、
  隐式动作清单（退出重进、切后台、杀进程、断网、另一设备、切号、TTL 到期、连点、中途打断、他人修改）、
  人（代码之外的动作：后台、客服、其他系统）。
- **覆盖度用计算出来的缺口闭环**，不靠头脑风暴（脚本只在已声明的读写点和原子上检查，读写点找全靠代码可见性，需求映射仍需人工）：
  - 孤儿写入点：某个写入点没有任何原子触达 → 要么漏了原子，要么是非用户触发的写入，都要写明
  - 孤儿读取点、空原子、读写集重复的原子
  - 替换型原子漏写的字段：一个动作"产出对象的新版本"却没重写某些字段 → 最强的缺陷信号
  - 隐式动作清单每项必须作答：引用已有原子 id，或 `N/A: 理由`；自由文本、不存在的原子 id 都判为无效
  - 缺少层信息的读写点（否则异步窗口、读写层不对称检查会被静默跳过）
- **唯一必做的人工检查点**放在原子表上：原子表是人能最快判断对错的最小产物，错了后面全部白做。
- 看不到代码的服务显式记为**盲区**，不假装覆盖。

## 目录

```text
whitebox-op-combo/
├── SKILL.md                     agent 入口：工作流与检查点
├── references/
│   ├── atomization.md           原子定义、范围锚点、四来源、覆盖闭环、atoms.json 结构
│   ├── defect-patterns.md       8 类缺陷模式 + 排除检查
│   ├── verification.md          状态标记、复现、定级、归属、快速指纹
│   └── output-templates.md      atoms.md / analysis.md / cases.md 模板
├── scripts/op_matrix.py         覆盖检查 + 组合剪枝 + 三元链 + 中断点（仅标准库）
├── examples/ai-search-answer-card/
│   ├── atoms.json               真实功能的读写点与原子
│   └── pairs.md                 脚本输出
└── tests/test_op_matrix.py
```

## 脚本

```bash
python3 scripts/op_matrix.py examples/ai-search-answer-card/atoms.json --out /tmp/pairs.md [--max-chains 30]
python3 -m pytest -q tests/
```

输出包含：覆盖缺口、带依赖标记的有序对（RAW / WAW / STALE / RACE / LAYER 与得分）、剪枝统计、三元穿透链、中断点。
atoms.json 结构错误（缺必填字段、id 重复、引用不存在的读写点或原子、`represented_by` 链或环）时返回 1。

## 产物

默认落在 `whitebox-output/{slug}/`：`baseline.md`、`atoms.json`、`atoms.md`、`pairs.md`、`analysis.md`、`cases.md`。
`cases.md` 与 `case-lite` 的 `full.md` 格式兼容，可用 case-lite 的写回脚本写回搬山（写回前须用户授权并 dry-run）。
