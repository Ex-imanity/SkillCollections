# 前端 Web 条件偏好

适用于现有 Web 仓库的实现、修复和评审。这些是 skill 的条件偏好，依据三个仓库的
有限样本整理，不是四位作者共同发布的团队标准。先遵守当前指令与仓库显式规范，
再判断条件是否匹配；只读目标仓库资料，不把其他产品或框架的写法迁入当前模块。

## F1. 先确定产品、框架和代码所在层

- 确认目标 package、路由入口、构建配置和组件形态。现有 Vue Options API、React
  函数组件、imis 配置页面分别沿用已有边界，不因风格改动迁移框架或语言。
- C 端 H5 先检查普通浏览器、App WebView、小程序及 SSR 的实际分支；B 端后台
  先检查表格/表单、权限、路由与部署前缀。不要把移动端布局或 bridge 套到后台。
- 单产品能力留在该产品层；有实际重复且语义一致时，才提到业务共享或基础层。
  同时核对所有调用入口、品牌差异、alias 和路由，不能只移动文件。
- 证据：mweb M1/M5、community C4/C7、internal-ad IA7（编号见各仓库资料）。

## F2. 在请求边界明确输入与返回契约

- 读目标 service/API 注册、请求实例与 interceptor，再读同类消费代码。保留认证、
  公参、签名、编码、服务前缀、环境选择和已有错误处理，不另建裸请求绕过它们。
- 明确 wrapper 返回 transport response、业务 envelope 还是已解包的数据；按具体
  接口读取 `code`、`data`、`list`、`pager`，不猜测多层 fallback 或套统一成功码。
- UI 分页字段与接口字段在已有适配边界转换。筛选值 `0`、`false`、空字符串、
  `null`、`undefined` 分别按协议处理，不用 truthy 判断统一过滤。字符串 ID 保持
  字符串；类型、响应键、清空语义和数值精度都属于兼容契约。
- TypeScript 模块复用其请求/响应类型；类型与消费同步修改，不用 `any` 掩盖错层级。
  JavaScript 模块按本地约定实现，不为了风格一致引入 TS 或一套 DTO 框架。
- 证据：community C1、mweb M3、internal-ad IA1/IA2/IA6。

## F3. 展示、编辑和提交值分清职责

- 复用当前 computed、selector、formatter 或局部方法表达展示衍生值，避免模板中
  重复拼接复杂字段。占位图和缺省文案只作用于展示，不回写原字段或提交占位资源。
- 编辑回填保留合法的 `0`/`false`；切换开关、隐藏字段、清空和取消分别核对业务语义。
  服务端缺失字段不使用生产 mock 数据掩盖。缺省处理不能吞掉应暴露的协议错误。
- 默认推荐/异步回填不得覆盖用户已编辑或确认的值；检查请求返回时的状态，不能
  只依赖发请求前的条件。这项是兼容性检查，并非样本已证明处理了所有竞态。
- 证据：mweb M2（含 mock 反例）、community C2/C3、internal-ad IA4。

## F4. 沿用状态和生命周期的归属

- 局部弹窗与草稿沿用组件状态、props/emit 或现有 hooks；跨页共享沿用现有
  store/model。选择依据是实际职责，不规定所有状态必须进 store 或全部留在组件。
- loading、操作锁、成功/失败提示、确认后刷新、重置筛选与页码保持当前流程。
  若存在缓存，检查表单值、选项、分页、key/TTL 与重置是否一致；不默认新增缓存。
- 检查 watcher 的数据依赖和提交顺序、effect 实际读取的依赖及请求完成标记。
  空数组可能是成功结果，不用“有数据”代替“请求完成”；避免回写触发循环。
- 浏览器 SDK、window/document 和 DOM 操作放在允许的客户端执行路径；按现有
  生命周期处理监听、timer、节流和 Object URL 清理。节流参数是场景选择。
- 证据：mweb M5/M7、community C3/C5/C7、internal-ad IA3/IA5/IA8。

## F5. 保留完整的用户动作链路

- 修改跳转、分享或上传时，沿着入口读到路由/bridge/埋点/API：保留 source、
  协议参数、权限、端内外分支和资源表示，不只改最终 URL 或一个组件回调。
- 稳定的重复业务规则提为小型领域 helper 或复用已有常量；单处使用保留局部表达。
  不把场景专属参数升级成全产品配置，不因字面量出现就新增全局枚举体系。
- 用户内容渲染沿用已确认的转义、许可与 scheme 处理边界。关闭 lint 安全规则
  不是渲染任意 HTML 的授权；历史 regex helper 不是已验证的通用 sanitizer。
- 证据：mweb M4/M6、community C4/C5/C6、internal-ad IA1/IA5。

## F6. 格式、样式和验证跟随当前模块

- 核对当前作用域 editorconfig、formatter、lint 和 Less/CSS 组织。新增选择器用
  目标模块的业务语义命名，模板与样式同步；不强制所有仓库采用 BEM 或 CSS Modules。
- 格式配置与历史作者缩进冲突时采用适用配置；只改涉及区域。禁用规则、配置拼写
  错误或过期 README 不能推导为推荐规范，也不能证明检查命令有效。
- 检查 package scripts 是否存在并覆盖本次文件；按项目规则执行必要检查。对请求
  改动验证实际返回层级和失败路径；对表单验证回填/清空/0/false；对 H5 生命周期
  验证实际受影响端；UI 改动按仓库要求检查目标视口，不套统一测试清单。
- 证据：mweb M8 及格式配置、community 配置冲突、internal-ad 显式规则与配置冲突。
